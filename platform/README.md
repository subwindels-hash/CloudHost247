# CloudHost247 Platform

A full-stack, monolithic, dependency-free Node.js platform that replaces the Fastify/TypeScript
`cloudhost247-node` stack, shipped together with a Vanilla-JS public site, a React + Vite SPA,
PWA support, and Capacitor native-app shells.

The monolith (`server.js`) uses **Node core modules only** — `http`, `fs`, `path`, `crypto` — plus
**one** production dependency, `pg@8.16.3`, which is loaded lazily *and only* when `DATABASE_URL`
is set. With no `DATABASE_URL`, the platform runs on a zero-dependency JSON file store.

Runtime: **Node.js >=22.20.0 <25**.

---

## Layout

```
platform/
├── server.js              # single entry point: config + storage + http listener + shutdown
├── package.json           # engines node >=22.20.0 <25 ; single dependency pg@8.16.3
├── src/
│   ├── app.js             # assembles router, middleware, domains, static serving
│   ├── core/              # the zero-dependency framework we replaced Fastify with
│   │   ├── router.js      #   routing (params, wildcards, 405)        <- Fastify router
│   │   ├── http.js        #   request/response ctx, body parse        <- fastify req/reply
│   │   ├── validate.js    #   schema DSL                              <- zod
│   │   ├── config.js      #   .env parser + env schema                <- dotenv + zod env
│   │   ├── logger.js      #   structured logger                       <- pino
│   │   ├── security.js    #   security headers                        <- @fastify/helmet
│   │   ├── cors.js        #   CORS                                    <- @fastify/cors
│   │   ├── ratelimit.js   #   fixed-window rate limiting              <- @fastify/rate-limit
│   │   ├── static.js      #   static files, etag/304, ranges, gzip/br <- @fastify/static
│   │   └── errors.js      #   HttpError hierarchy (wire-compatible with the old platform)
│   ├── lib/
│   │   ├── password.js    #   scrypt hash/verify                      <- bcryptjs
│   │   ├── jwt.js         #   HS256 sign/verify (wire-compatible)     <- jsonwebtoken
│   │   ├── totp.js        #   RFC 6238 TOTP + recovery codes          <- (qrcode/otp deps)
│   │   ├── base32.js      #   RFC 4648 base32
│   │   ├── auth.js        #   authenticate()/requireRole() middleware <- lib/require-auth.ts
│   │   └── ids.js         #   uuidv7, random tokens, customer ids
│   ├── store/
│   │   ├── schema.js      #   single source of truth for table shapes
│   │   ├── json-store.js  #   zero-dependency default backend (files under DATA_DIR)
│   │   ├── pg-store.js    #   PostgreSQL adapter (same repository API, SQL generated)
│   │   └── index.js       #   picks backend from config
│   └── domains/           # feature modules (each exports { name, register })
│       ├── health.js      #   /health /ready /api/v1/system/status
│       ├── auth.js        #   register/login/refresh/logout/MFA/password lifecycle
│       ├── account.js     #   profile/services/domains/tickets (caller-scoped)
│       └── catalog.js     #   public catalog reads + admin catalog CRUD
├── public/                # Vanilla JS public site (no build step) + PWA assets
│   ├── *.html             #   crawlable static pages
│   ├── assets/            #   css + vanilla ES modules
│   ├── sw.js              #   service worker (offline shell + cache strategies)
│   ├── manifest.webmanifest
│   └── icons/             #   PNGs generated by scripts/generate-icons.js
├── spa/                   # React + Vite customer dashboard (built to spa/dist, served at /app)
├── mobile/                # Capacitor shells (Android/iOS) wrapping the SPA
├── scripts/
│   ├── migrate.js         #   PostgreSQL schema migration (only path that needs pg)
│   ├── seed.js            #   idempotent dev seed (roles + sample catalog), both backends
│   └── generate-icons.js  #   dependency-free PNG icon generator
└── tests/                 # node:test — unit + real-HTTP integration
```

## Quick start (zero dependencies)

```bash
cd platform
node scripts/seed.js        # optional: load sample catalog
node server.js              # boots on http://localhost:3000 (PORT from env)
```

With no `.env` and no `DATABASE_URL`, an ephemeral JWT secret is generated and logged, and data is
stored in `platform/data/*.json`. This is the intended development path.

For a permanent secret:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
# put the output in .env as JWT_SECRET=...
```

## PostgreSQL mode (the single dependency)

```bash
npm install                 # installs only pg@8.16.3
DATABASE_URL=postgresql://user:pass@host:5432/cloudhost247 node scripts/migrate.js up
DATABASE_URL=postgresql://... node server.js
```

Everything else is identical — the repositories expose the same API on both backends.

## Frontends

| Frontend | Where | How served |
|----------|-------|------------|
| Public site (Vanilla JS) | `public/` | static, crawlable, no build step, offline-capable via `sw.js` |
| Dashboard (React SPA) | `spa/` | `npm run spa:build` → `spa/dist`, mounted at `/app` with SPA fallback |
| PWA | both | `manifest.webmanifest` + `sw.js` + generated icons |
| Native apps | `mobile/` | Capacitor wraps the SPA build (see `mobile/README.md` is `docs` below) |

The SPA dev server proxies `/api` to the monolith; in production the monolith serves the built SPA
and the same-origin API, so auth tokens work without CORS.

## API surface (ported so far)

- `GET /health`, `/ready`, `/api/v1/system/status`
- `POST /api/v1/auth/register|login|refresh|logout`, `GET /api/v1/auth/me`
- `POST /api/v1/auth/password/change|forgot|reset`, `POST /api/v1/auth/email/verify-request|verify`
- MFA: `POST /api/v1/auth/mfa/totp/enroll|confirm|disable`, `GET /api/v1/auth/mfa/status`
  (legacy `/api/auth/*` aliases registered for existing clients)
- Account: `PATCH/GET /api/v1/account/profile`, `GET services|domains|tickets`, `POST tickets`,
  `GET tickets/:id`, `POST tickets/:id/replies`
- Catalog: `GET /api/v1/catalog`, `/products`, `/products/:slug`, `/products/:slug/plans`,
  plus role-gated `admin` CRUD
- `GET /api` — machine-readable route index

## Tests

```bash
npm test
```

The integration tests boot the real app on an ephemeral port and drive it over HTTP — no mocking of
the request path — covering auth, MFA, session invalidation, RBAC, static caching/304, and traversal
protection.
