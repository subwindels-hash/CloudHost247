BEFORE YOU DEPLOY
  - Confirm the cPanel account has Setup Node.js App/Passenger and Node.js >= 20.9.0.
  - Confirm PostgreSQL access, terminal/npm install access, domain routing, and HTTPS.
  - Real cPanel staging has NOT been performed; use docs/CPANEL_DEPLOYMENT.md as the
    authoritative deployment checklist and close its staging gate before production.

DEPLOY
  1. Upload the ZIP to cPanel File Manager, extract it, and move the contents of
     cloudhost247-cpanel-<git-sha>/ into your application root, overwriting dist/,
     public/, manifests/, database/migrations/ and server.js. Never overwrite .env.
  2. Create a Production Node.js app with startup file server.js. Passenger supplies PORT;
     do not configure PORT yourself.
  3. Configure the active variables from .env in cPanel's Environment Variables UI
     (recommended), or upload the customized .env with mode 600.
  4. In the cPanel virtual-environment terminal, run: npm ci --omit=dev
  5. Run: npm run env:check
  6. Review migration status, back up the database, then follow docs/CPANEL_DEPLOYMENT.md
     §0a/§6. Migrations 0023, 0024, 0025, and 0041 are quarantined in production and
     require explicit owner authorization before applying.
  7. Restart the app; verify /health, /ready, and the final application URL.
  8. Schedule the worker as a one-shot cron job using the actual cPanel paths:
     * * * * * cd <APP_ROOT> && <NODE_PATH> dist/src/worker/main.js --once
