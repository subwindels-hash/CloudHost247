# CloudHost247 Tools inventory

Audited 2026-10-06, before implementation, against repository commit `1fafb53`.
`AUDIT-FILES.json` records matching source paths and hashes, including services,
controllers, migrations, tests, legacy integrations, caches and documentation.
The audit inspected implementation files, not just previous READMEs.

## Status semantics

**COMPLETE** = an existing core implementation and consumer are present, not a
claim of production acceptance. **PARTIAL** = provider/runtime/UI/security work
remains. **MISSING** = absent from the consolidated Tools registry. Runtime
availability still comes from the effective registry, never this document.
At baseline, all tools needed canonical discovery, global integration and SEO work.
The baseline tables below are preserved as the audit record; the implementation
update at the end records what changed and what remains deployment-dependent.

## Existing WHMCS addon — separate execution surface, retained

`modules/addons/cloudhost247_tools/cloudhost247_tools.php` owns its registry;
`includes/classes.php` owns admin/client controllers; `includes/api.php` owns the
executor. AJAX is POST + WHMCS CSRF at `index.php?m=cloudhost247_tools&action=ajax`;
REST is token-authenticated at `modules/addons/cloudhost247_tools/api/index.php`.
Guest pages remain at `index.php?m=cloudhost247_tools`; original consumers stay intact.
Caching uses `mod_cloudhost247_tools_cache`, with random/reflected/live probes
exempt; configured TTL is 5–30 minutes. Per-IP AJAX and hashed-token REST budgets
use a 60-second window. `tests/tools/run.php` and `tests/tools/test_static.py`
cover the module. Its old HTTP/socket helpers do not provide the Node client's
complete pinning/redirect/size boundary: **do not advertise this legacy surface
as the newly reviewed diagnostic backend**. Preserve routes; no silent migration
of credentials, sessions or stored history.

### Repaired integration gaps

- Canonical/category routes and aliases, server metadata, unknown-tool 404s;
  shared header/footer availability projection; all tools available-first search.
- Labeled forms, client validation, structured actual responses, copy/export,
  loading/error/configuration/auth states, related tools and explanations.
- Domain-health no longer sends embedded visitors into an unmounted SPA route:
  the canonical tool uses the existing backend and ownership/auth gates, with a
  valid platform handoff from WHMCS. Its old platform route
  remains available. Speed now performs real bounded browser transfers using
  the existing APIs instead of displaying configuration as a speed measurement.
- QR results have an actual image/download view, not a substituted sample image.
- Cache normalization/truncation, compressed IPv6 parsing, decompression size,
  interrupted response and RDAP referral transport issues were repaired; see
  TOOLS-SECURITY.md. Legacy PHP network execution was not newly promoted.
- Unconfigured WHOIS/BIN/OCR/reverse-IP providers and missing system capabilities
  remain explicitly unavailable and absent from public global tool links.

### Not newly implemented

The DNSChecker comparison contains additional features such as RAID, Morse,
htaccess/rewrite generation, social handle checking and proprietary color matching.
They are not silently presented as working tools. See the parity matrix for the
exact omissions. Neither licensed WHMCS runtime verification nor real external
provider credentials are available in this workspace; local reports are scoped
accordingly. Existing provider-specific functionality remains configurable through
its existing admin module rather than being simulated in the Tools Center.
