# Canonical Node Backend — Route-by-Route & Feature-by-Feature Comparison

**Date:** 2026-11-07 · **Branch:** `arena/1b329121-cloudhost247` · **Decision:** see [`docs/ARCHITECTURE-DECISION-RECORD.md`](ARCHITECTURE-DECISION-RECORD.md)
**Machine-readable route diff:** [`docs/audit/canonical-backend-route-comparison.csv`](audit/canonical-backend-route-comparison.csv) — 838 method+path rows, one per canonical route, with `in_cloudhost247_node` / `in_platform` / `classification`.

> `platform/README.md` opens with "replaces the Fastify/TypeScript `cloudhost247-node` stack". That is a **claim**, not a fact. This document tests it. **It is false**: `platform/` is a substantial but incomplete port, and switching to it now would delete working customer functionality.

---

## 1. How the comparison was produced

Both applications were booted in this workspace and their **actual registered route tables** were dumped — not read from documentation.

| Stack | Method | Result |
| --- | --- | --- |
| `platform/` | `node platform/dump-routes.cjs` → `app.router.list()` | 720 raw `METHOD /path` registrations |
| `cloudhost247-node/` | `buildApp(env,{serveFrontend:false,pool:new PGlite()})` → `await app.ready()` → `app.printRoutes({commonPrefix:false})`, tree parsed into flat routes | 841 raw registrations before de-duplication |

Routes were canonicalised for comparison: `/api/v1/x` ≡ `/api/x` (both stacks deliberately keep legacy aliases), all `:param` names → `:p`, and Fastify's merged `:a|:b` nodes collapsed. HEAD (auto-generated by Fastify) was excluded.

## 4. Answer to the question asked

**Is `platform/` the complete replacement?** **No.**

Its own `platform/MIGRATION.md` §"Deliberately deferred (open items)" states, in the project's own words, that these are not ported: real payment checkout initiation, domain availability lookup, the order-driven provisioning path, real provider egress, real browser/hardware WebAuthn ceremonies, and (at the time of writing) large domains. Independently we confirmed **222 API endpoints, the entire builder/AI-builder/store/logo-maker/experts/marketing/inbox product surface, all AI/LLM integration, all 83 versioned migrations, the WHMCS/PHP shared-generator integration, and the 131-page React application exist only in `cloudhost247-node/`.**

Switching now would:
- delete working customer functionality (violates "Do not delete existing functionality, migrations, data, or integrations"),
- break the PHP/WHMCS ↔ Node consistency guaranteed by `scripts/site/generate.mjs`,
- discard the checksummed migration/quarantine controls required by the financial freeze,
- and orphan the 168-file Vitest suite.

`platform/` is nonetheless a **valuable, tested parallel implementation** (876 tests, zero-dependency core, PWA/mobile, static public site, gateway webhook parsers, in-tree WebAuthn, manifest catalogue). Nothing here proposes deleting or rewriting it.

## 5. Decision and transition rules

See [`docs/ARCHITECTURE-DECISION-RECORD.md`](ARCHITECTURE-DECISION-RECORD.md). Summary:

1. **`cloudhost247-node/` is the canonical Node backend.** All Phase 3–9 backend work happens there.
2. **`platform/` is frozen read-only for feature work.** No new domains, no schema changes, no parallel implementations of existing services. Its files, tests, manifests, migrations notes and data stay in the repository untouched.
3. **No deletion, no data migration, no service duplication.** The 116 platform-only routes are recorded as capabilities to be *absorbed* later, not rebuilt twice today.
4. **Convergence is a separate, explicitly authorised project**: port the platform-only capabilities into the canonical stack (or vice versa) only after a parity gate where the route diff reaches 0 node-only/0 platform-only, both test suites pass, and the WHMCS/PHP generator projects into the chosen frontend.
5. **`platform/README.md`'s supersession claim is qualified** in place with a pointer to this comparison, so nobody acts on a stale assertion.
6. The P0 UUID defect was fixed in the canonical stack only; `platform/src/core/validate.js:218` already uses a version-agnostic UUID regex and does not have this defect.
