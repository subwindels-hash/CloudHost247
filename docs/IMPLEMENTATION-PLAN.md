### 1.1 The five architectural constraints

1. **Preserve.** WHMCS/PHP application, React/Node app, all APIs, all 83 migrations, auth, Admin/Super Admin, catalogue, cart/checkout, payments, provisioning modules, and the shared registries stay. Nothing is deleted or replaced wholesale.
2. **No duplicate services.** The brief explicitly forbids a second implementation of an existing service without a clear architectural reason. `AR04` (two complete Node stacks) is the one existing violation that must be resolved *before* adding backend features.
3. **Consistency.** `scripts/site/generate.mjs` is the only mechanism that projects navigation/design into both PHP and SPA. Any new public page, chrome change or theme token must go through `shared/site/registry.json` / `shared/site/design-system.css`, not direct edits to generated copies.
4. **Truthfulness.** Where cPanel already provides a function, integrate with it; never rebuild it. Every domain operation must call a real registrar API. Every infrastructure action must fail closed when a provider is unconfigured; **never return success before provider confirmation**. No uptime, security or backup claim before verification.
5. **Financial freeze.** Migrations `0023`/`0024`/`0025`/`0041` are quarantined in `cloudhost247-node/database/migrate.ts`; webhooks are frozen; PR #12 is open. No gateway activation or financial setting change without written authorisation.

## 13. Explicit non-goals for this plan

- No Hostinger source code, imagery, copy or trademarks.
- No production deploy, no live gateway activation, no financial setting change without D2.
- No simulated successful provisioning; no unverified uptime/security/backup claims.
- No invented customer stories, testimonials, prices, TLD fees or AI capabilities.
- No second implementation of an existing service (D1 resolves the one pre-existing duplication).
- No direct edits to generated files (`registry.generated.ts`, `pages.generated.json`, `site.json`, `frontend/public/docs/*`, `robots.txt`).
