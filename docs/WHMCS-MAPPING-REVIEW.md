## What approval would authorise

Approving a VERIFIED row authorises exactly one `bind` command for that service, and nothing else:
no price is copied into the SPA, no purchase button changes, and no checkout is enabled. Those are
C2 decisions taken service by service after this review.

## How a reviewer proposes a mapping

Write `config/whmcs/mapping-proposal.json` by hand from the discovery artifact — never from a guess.
Then re-run `npm run whmcs:review`, and only after this document is approved, bind one
service at a time with `npm run whmcs:map -- bind --service <key> --product <pid>`.

```json
{
  "notes": "who proposed this, against which discovery run",
  "baseUrlFingerprint": "<copy from config/whmcs/catalogue-snapshot.json>",
  "entries": [
    { "serviceKey": "hosting-vps", "productId": 0, "cycles": ["monthly", "annually"], "note": "why" }
  ]
}
```

`productId` stays `0` in this example on purpose: a real id may only come from the discovery
artifact. Omitting `cycles` offers every cycle WHMCS prices for the product.
