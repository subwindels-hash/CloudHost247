# `shared/site` — the website's single source of truth

Everything in this directory is authored content or the design system. It is the only place a
product, a menu entry, a footer link, a policy or a colour is defined. Both websites this
organisation publishes are generated from it:

* the **CloudHost247 Node platform** (`cloudhost247-node/`), which serves the live site and the
  client area;
* the **WHMCS/PHP site** (root `*.php` + `templates/cloudhost247/`).

## What is here

| File | What it is | Who reads it |
|---|---|---|
| `registry.json` | Brand, 9 mega menus, 9 footer columns, utility links, legal index, tool categories, sitemap policy | generator → both websites |
| `design-system.css` | **Canonical stylesheet**: tokens, components, breakpoints, motion policy | the SPA (imported) and the PHP theme (generated copy) |
| `content/*.json` | Every marketing page: hero, sections, FAQs, related services, SEO metadata | generator → the SPA page renderer |
| `content/legal/*.txt` | Policy text extracted from the signed PDFs, committed so builds need no PDF tooling | `extract-legal.mjs` |
| `content/news.json` | Release notes, each with its own stated limitation | the blog page |
| `generated/route-report.json` | Machine-readable audit output from the last generation run | audit, report |

Generated artefacts (never edit; they are overwritten):

```
cloudhost247-node/src/navigation/registry.generated.ts
cloudhost247-node/frontend/src/navigation/registry.generated.ts
cloudhost247-node/frontend/src/content/{pages,docs,tools,legal}.generated.json
cloudhost247-node/frontend/public/{media,docs}/
modules/addons/cloudhost247_theme/resources/site.json      (navigation + footer only)
templates/cloudhost247/css/design-system.css
```

## Regenerating

```bash
node scripts/site/extract-legal.mjs   # policy PDFs / theme documents → legal.generated.json
node scripts/site/generate.mjs        # registry + content → every generated artefact
node scripts/site/check-links.mjs     # prove every published link resolves
```

`generate.mjs --check` validates without writing, which is what CI should run.

## The rules the generator enforces

1. **Every destination resolves.** A menu or footer link must match a declared SPA route, a
   marketing page, a legal document, a tool path, a shipped PHP file, or a licensed WHMCS entry
   point. Anything else fails the build.
2. **Every published route has a page.** A route the navigation advertises but no page serves is an
   error, not a warning.
3. **Every route has an inbound link.** `marketing-pages.test.tsx` fails and lists any page that
   cannot be reached from a menu, the footer or another page.
4. **Content is complete.** SEO titles ≤ 75 characters, descriptions 70–165 characters, every
   section type known, every icon implemented, every illustration present on disk.
5. **No placeholder copy.** The render tests reject "coming soon", "not yet built", "lorem ipsum"
   and similar holding text on any public page.
6. **One design system.** The PHP theme's stylesheet is a generated byte-identical copy; the test
   suite fails if the two diverge.

## Honesty rules the content follows

These are not style preferences — they are why several pages look shorter than they could:

* prices, plans and availability come from the live catalogue, never from markup;
* data-centre regions come from configuration; an unconfigured deployment shows an empty state;
* the status page reports only checks the platform can actually run, and labels everything else
  "not monitored";
* no uptime percentage, certification or customer count is published unless it is a fact;
* where a capability does not exist (Kubernetes, a productised WAF, a CDN), the page says so
  instead of implying it.
